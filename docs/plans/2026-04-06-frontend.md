# LocalSearch — Frontend Implementation Plan

> **Reference:** `context/frontend_implementation.md` (880 lines, staff-level spec)
> **Reference diagrams:** `context/img1.png` (query state machine), `context/img2.png` (data flow)
> **Tech stack:** Swift 5.10+, SwiftUI, AppKit interop, macOS 14+ (Sonoma)
> **Testing:** XCTest + ViewInspector for SwiftUI unit tests, XCUITest for integration
> **Dependency:** Rust engine FFI ready at Task 21 of `2026-04-06-localsearch-core.md`

---

## Architecture Summary

```
SearchWindowController (NSWindowController)
└── SearchWindow (NSPanel, .nonactivatingPanel)
    └── SwiftUI hosting root
        ├── SearchViewModel (@MainActor ObservableObject) — single source of truth
        ├── Transport layer: Debounce | PrefixCache | FFIBackend
        └── Backend: Rust core via C FFI (`liblocalsearch.dylib`)
```

**Invariants from spec (§1):**
- Monotonic responsiveness — no keypress ever blocks main thread
- Stale results dimmed immediately (synchronous) before async work starts
- System state always visible — no silent degradation
- No phantom confidence — REVOKED permission shown before user clicks
- Cancellation via `queryGeneration: UInt64` counter, not timing
