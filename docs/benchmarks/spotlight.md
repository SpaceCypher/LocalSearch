# LocalSearch vs Spotlight

Generated by `cargo run --release --example bench_vs_spotlight`.

## Setup

- Machine: Apple M3, 8 GB RAM
- macOS 26.3
- LocalSearch commit `e040a67`, release build
- Scope for both: `~/Downloads`, `~/Documents`, `~/Desktop` (59639 items in the LocalSearch index)
- Both are called in-process: LocalSearch through `Engine::search`, Spotlight through `MDQueryExecute` (synchronous). No `mdfind` process start-up is included.
- Both are capped at 100 results per query.
- Each query: 3 warm-up runs, then up to 30 measured runs (fewer if the query used more than 20 s in total). Times are milliseconds.

## Time until a new file is findable

A file with a unique name is created in an indexed folder and both engines are polled every 10 ms until they return it.

- LocalSearch: 0.42 s (median of 5; range 0.40–0.73 s)
- Spotlight: 1.95 s (median of 5; range 1.85–2.57 s)

## Searching while the index is being saved

LocalSearch periodically writes its whole index to disk. One query (`report`) is repeated continuously on another thread before and during a save.

- Before the save: median 10.9 ms, worst 18.0 ms (178 queries)
- During the save (1.0 s): median 15.0 ms, worst 117 ms (62 queries)

## LocalSearch resource cost

Spotlight's index is built and held by the system for every app, so there is no equivalent per-app figure to set beside these.

- First index, names only: 4.1 s for 59639 items (search is usable from here)
- First index, names and contents: 58.0 s in total
- Share of text, code and PDF files whose contents were indexed: 79% (stopped at the 256 MB in-memory index budget)
- Process memory right after the first index: 391 MB
- Process memory after loading the saved index in a fresh process: 341 MB
- Index on disk: 43 MB
- Loading the saved index on a later launch: 1.60 s for 59639 items

## What this does not show

- One machine, one set of files. Numbers will differ elsewhere.
- Spotlight indexes the whole machine and many more file types (Office documents, mail, images); LocalSearch here covers three folders and reads only text, code and PDF contents. Hit counts are therefore not a measure of which is more complete.
- Spotlight needs no index build by the user and no extra memory in the app.
- The typo queries are included because LocalSearch tolerates misspellings and Spotlight matches literally; zero Spotlight hits there is expected behaviour, not a failure.
- The engines do not interpret a query the same way. For several words LocalSearch returns files matching any of them (ranked by how many match); the Spotlight queries here require every word. LocalSearch also returns approximate matches, so its hit counts include loose ones.
- Result quality (whether the best file is ranked first) is not measured.
- Known anomaly, not shown above: in an earlier run of this benchmark on the same machine, the first execution of one LocalSearch query (`license`) took about 10 s. It did not recur in this run and the cause has not been identified. Saving the index was tested as an explanation and ruled out (see "Searching while the index is being saved").
